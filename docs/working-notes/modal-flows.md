Build two modal flows that share components but represent two different user actions. The system must be built entirely using Material UI components and the existing design system. Do not create custom UI patterns, custom dropdowns, or custom color systems. The goal is to maintain a consistent component system while supporting two different workflows that occur in different parts of the application.

The first modal flow exists on the Plots page and is used to create a new treatment and immediately assign it to one or multiple plots. This modal should open when the user selects one or multiple plots and clicks the action “Add Treatment to Plots”. Because the user selected plots before opening the modal, those plots must already be preselected when the modal opens. The user should still be able to add or remove plots if needed.

This modal is used to create a new treatment, therefore all treatment input fields must be visible. The modal must contain a title that matches the action label “Add Treatment to Plots”. Below the title there should be a short explanatory sentence explaining that the user can create a treatment and assign it to selected plots. The form fields include Date, Status, Product, Dose, Water Volume, and Plots. Date must be a date picker using the format dd.mm.yyyy. Status must be a dropdown with the default value “Applied”. Product must be a searchable selector using the same selector pattern that already exists in the filtering UI. Dose and Water Volume must be numeric inputs with the unit label L/ha. The Plots field must be a multi-select selector. Because the modal was opened from the Plots page, the plots selected earlier must appear preselected inside this field. Selected plots should appear below the selector as removable chips showing the plot identifiers. The footer must contain a Cancel button on the left and a primary action button labeled “Add Treatment” on the right.

The second modal flow exists on the Treatments page and is used to assign an existing treatment to one or more plots. In this context the treatment already exists, so the user should not be able to edit treatment details. Instead, the modal should display a summary of the selected treatment or treatments and only allow the user to choose plots. This modal opens from two different entry points: either the user selects one or multiple treatments and clicks the bulk action “Assign Treatments to Plots”, or the user opens the row action menu of a single treatment and selects “Assign Treatment to Plots”. In both cases the same modal structure should be used.

The modal title must match the action text that opened it. Below the title there should be a short explanation stating that the user can assign the selected treatment or treatments to plots. Instead of editable fields for Date, Product, Dose, or Water Volume, the modal should display a treatment summary section. If a single treatment was selected, the summary should show the treatment details such as Product, Date, Dose, and Water Volume. If multiple treatments were selected, the modal should show a small summary indicating how many treatments are selected, for example “2 treatments selected”. In both cases the only editable control in the form should be the Plots selector.

The Plots selector must behave consistently across both modal flows. It should be implemented using a Material UI multi-select pattern such as Autocomplete with multiple selection. The input field should show the placeholder “Select plots…”. When opened it should display a searchable list of plots with checkboxes. When plots are selected they should appear below the input as chips showing the plot identifiers. Each chip must include a small remove icon so users can remove plots individually. A reset option should also be available to clear all selections.

Both modal types must use the same reusable components wherever possible. For example the Plots selector should be implemented as a reusable component used by both modals. Treatment summaries should be displayed using a reusable treatment summary component. The modals themselves should follow the same layout structure using Material UI Dialog with a header, content area, and footer. The header must contain the title and a close icon. The footer must contain Cancel and a primary action button aligned to the right.

The primary action button must change its label depending on the context. In the creation flow it must say “Add Treatment”. In the assignment flow it must say “Assign to Plots”. The styling of the button and all other components must follow the Material UI theme and use the single primary color defined in the system. Do not introduce additional colors such as red accents or custom styling that breaks the design system.

The final result should therefore consist of two modal flows with shared UI components. The first modal is used to create a treatment and assign it to plots from the Plots page. The second modal is used to assign existing treatments to plots from the Treatments page. Both must be implemented using Material UI components, must follow the design system, and must reuse components rather than creating separate one-off implementations.
